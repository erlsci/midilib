## The six Blockers (distinct defects)

1. **`midifile` SysEx read off-by-one** — erlang #1 / spec S2. The `F0` byte is unaccounted; the track byte-counter desyncs and parsing crashes. `src/midifile.erl:193-199`. *(New — not in the seed set.)*
2. **`seq_name` written with the End-of-Track type byte** (`0x2F` for `0x03`) — erlang #2 / spec S3. `src/midifile.erl:319-321`.
3. **`track_end` read/write shape mismatch** (3-tuple vs 2-tuple) — erlang #3. No file read by the module can be written back. `src/midifile.erl:147` vs `:309`.
4. **SysEx codec is single-7-bit-byte; encode of a binary throws** — erlang #8 / spec S1 / consumer C1. The family's #1 cross-layer blocker (R7). `src/midibin.erl:137-138,410-411`.
5. *(near-blocker, graded High but family-fatal)* **`midimsg:batch` ⇄ `midibin` batch shapes are incompatible** — erlang #11 / consumer C3. The natural batch helper produces a value the codec rejects.
6. *(near-blocker, graded High)* **`write/2` hardcodes format 1, discarding the parsed format** — erlang #6 / spec S5.

(Strict Blockers by count: #1–#4 above = 4 in the erlang report + their spec/consumer mirrors. #5/#6 are graded High but listed here because each independently breaks a headline use case.)

## Architecture-doc discovery note

**No architecture or design document exists in this repository.** Searched: repo root (`README.md` only — feature blurbs, not design), no `CLAUDE.md`, no `docs/` or `design/` directory, no `-moduledoc` in any source module. The closest statements of intent are (a) the `midimsg.erl:11-16` header comment claiming a project-wide "lingua franca," which findings erlang #12 / consumer C2 show to be false, and (b) the downstream consumer bootstraps under `../midi/workbench/` and `../midiio/workbench/`, which are *consumer* design docs, not midilib design docs. Consequence: most invariants (channel base, failure representation, batch shape, who owns normalization) are unwritten and were reconstructed from source + consumer docs. This documentation gap is itself a finding (erlang #25) and a consumer risk (`midi` is being built against undocumented midilib behaviour).

## Cross-cutting findings → root-cause report

- **Three-vocabulary split** (`midimsg` `{midi,{N,D}}` vs `midifile` `{N,DT,V}` vs `midibin`'s subset): root cause **erlang #12**, fullest treatment **consumer C2**; ripples into the batch mismatch (#11/C3), channel base (#13/C7), and failure representation (#14/C4).
- **Process-dictionary state machine in `midifile`**: root cause **erlang #18**; underlies the module's untestability (#19) and is adjacent to the read/write asymmetries (#2, #3, #4, #7).
- **Untested high-risk surface**: **erlang #19/#20**; the reason every `midifile` Blocker (#1–#3) is invisible today.

## Trend note — dominant root-cause clusters

The planning analysis suspected two clusters; both are **confirmed**, and a third emerged:

1. **The vocabulary split (confirmed).** The single largest source of consumer-facing breakage. Three modules define three message shapes under a false "one common form" claim; `midibin` can encode only a subset of `midimsg`, and `midifile`'s 3-tuples match neither. Channel base (1- vs 0-based), batch shape, and error representation all fork along the same fault line. Fixing this is a prerequisite for the family's "one representation across realtime and files" goal.

2. **`midifile`'s process-dictionary running-status machine (confirmed).** `put`/`get` of `status`/`chan` thread hidden, non-reentrant state through ~20 clauses. It is why the module resists unit testing, and the read/write paths drift apart (track-end shape, seq-name type byte, sysex framing) precisely because no round-trip test ever exercised the pair. A state-threaded rewrite with `read(write(Seq)) =:= Seq` property tests would surface Blockers #1–#3 immediately.

3. **Inherited-code rot, untested (emergent).** Every Blocker lives in `midifile` (Jim Menard's 2010 origin), which has **zero tests**, while the modern, tested `midibin` is clean. The defects are not subtle once read; they survive only because the one test module covers `midibin` exclusively. The seed set's `midifile` running-status claim was, on verification, **refuted** (erlang clean-check #1) — confirming the brief's warning that the analyst's characterizations needed checking, and that the value of the audit was in what lay beyond the seed list (the SysEx read off-by-one, the velocity-loss-on-write, the quantiser, the batch incompatibility, the decode-completeness fuzziness).
